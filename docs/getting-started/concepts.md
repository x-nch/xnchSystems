Key concepts and terminology for understanding xnch + Nexi.

## xnch Overview

**xnch** is a cognitive control plane - a local-first, privacy-first system for executing multi-agent workflows with structured memory and audit logging.

### Key Properties

- **Local-First**: All data stays on your machine by default
- **Privacy-First**: No telemetry, no cloud dependencies
- **Structured Memory**: Context, outcomes, and patterns stored explicitly
- **Audit Logging**: Complete decision trail with cryptographic verification

## Nexi Overview

**Nexi** is the decision engine that sits between Intent Parser and Plan Compiler. It generates N candidate plans, evaluates them against policies and memory context, and selects the best option.

### Responsibilities

1. Generate multiple candidate plans from intent
2. Filter candidates against policy rules
3. Evaluate candidates across multiple dimensions
4. Select optimal decision with explainability

## Intent

An **Intent** is a normalized representation of user input.

```python
class Intent:
    raw_input: str
    intent_class: str        # e.g., "execute", "query", "create"
    action_type: str         # e.g., "run_command", "read_file"
    entity_class: str        # e.g., "file", "service", "data"
    parameters: Dict[str, Any]
    confidence: float
```

## Plan

A **Plan** is a candidate solution generated by Nexi.

```python
class Plan:
    plan_id: str
    intent_hash: str
    steps: List[Step]
    estimated_cost: float
    risk_score: float
    metadata: Dict[str, Any]
```

## Evaluation Dimensions

Nexi evaluates plans across four dimensions:

1. **Safety** - Does the plan cause harm?
2. **Efficiency** - Is the plan optimal in resources?
3. **Compliance** - Does the plan follow policies?
4. **Context Fit** - Does the plan match the current context?

## Memory Stores

| Store | Purpose | Technology |
|-------|---------|------------|
| Context Store | Current execution context | SQLite (WAL) |
| Vector Store | Semantic similarity search | sqlite-vec |
| KV Cache | Fast key-value lookups | Redis |
| Outcome Store | Historical outcome records | SQLite |
| Pattern Store | Learned patterns and heuristics | SQLite |
| Episodic Store | Individual learning episodes | SQLite |

## Audit System

### Event Log

Append-only log of all system events.

### Decision Ledger

JSONL with SHA-256 chain for cryptographic verification.

```
{"decision": "...", "hash": "sha256:abc123", "prev_hash": "sha256:def456"}
```

### Replay Engine

Capability to replay past decisions for debugging/audit.
